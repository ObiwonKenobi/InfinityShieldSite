Current Threat Brief

Thirty days defined by two internet-wide trust failures: the PHP2Shell flaws, now confirmed exploited and on the CISA KEV list, and a certificate authority whose keys could be recovered by hand, which cost it a root in Chrome on 27 Oct. Around them ran exploited edge-device zero-days, a supply-chain intrusion into Microsoft 365 tenants through a backup vendor, a GitHub Actions credential-theft campaign, and large breaches at Capcom and Sony.

Top items

PHP2Shell: critical flaws in PHP core

Critical · exploited · CISA KEV

Two critical flaws affect nearly every PHP version back to 5.4, across PHP-FPM, Apache mod_php, php-cgi, FrankenPHP, and LiteSpeed, with mod_php at highest risk. Wiz Research, Calif, and OpenAI's Codex Security team reported them, and the researchers say AI tools helped turn them into working exploits. Details leaked online on 20 Oct and PHP moved its release up to 21 Oct. Amazon logged attempts from 17 Oct, four days before the patches. Successful exploitation is now confirmed: Expel reported a compromised Apache mod_php host running PHP 8.4.26, and Trellix lists addresses that delivered PHP web shells and a Go remote-access agent. Recorded Future notes the full extent of compromise is still not established, and early attempts seen by Cloudflare, watchTowr, Patchstack, and others were unsuccessful. CISA added both CVEs to the KEV catalog on 26 Oct with a federal deadline of 29 Oct. Vendors still disagree on which CVE covers one of the code paths.

Action: Patch every PHP install now, including vendor appliances and hosted CMSs, and treat anything exposed since 17 Oct as possibly compromised: look for new .php files in web roots, PHP or Apache processes spawning shells, curl, or wget, and new binaries in /tmp or /dev/shm. Source backports exist for 7.4, 8.0, and 8.1, and distributions may ship fixes under older version numbers, so check changelogs for the CVEs. Where an application never accepts uploads, block multipart/form-data at the proxy. If a server shows signs of exploitation, assume the secrets on it were read, not just that a shell was dropped.

eMudhra CA: intermediate certificate keys trivially recoverable

Critical · root distrusted

Eight intermediate CA certificates from the Indian certificate authority eMudhra, six for TLS and two for code signing, were generated with far too little randomness. Each private key was smaller than 256, so anyone holding the public certificate could test every possible value; recovered keys included 4, 56, and 115. A researcher found it with a CCADB check on 17 Oct. eMudhra revoked the certificates on 18 Oct, Apple blocked them on 19 Oct, and Microsoft followed on 20 Oct, the day Mozilla made the incident public and decided to stop trusting the emSign ECC Root CA G3 in Firefox. On 22 Oct eMudhra said it would exit the global SSL/TLS business, blaming a flawed key-generation ceremony in April 2025 that went unnoticed for about 18 months. Chrome removed the emSign ECC Root CA G3 from its root store on 27 Oct, so sites still chaining to it now show warnings. Chrome has not yet decided what to do with eMudhra's G1 RSA roots.

ConnectWise Cloud Backup (formerly SkyKick) used to reach Microsoft 365 tenants

Critical · supply chain

Starting 15 Oct, attackers abused the backup platform's application identities to sign into customer Microsoft 365 tenants, so MFA never applied. Huntress confirmed unauthorized sign-ins in 162 tenants by 16 Oct and later found nearly 1,000 tenants with sign-in activity from the attacker's address, more than 300 of them successful. ConnectWise disabled seven application identities at 07:00 UTC on 17 Oct and suspended Cloud Backup, SaaS Security, and Cloud Management. On 21 Oct Microsoft attributed the campaign to Storm-0940, a China-aligned group, said it used ARTEX, an open-source agentic AI penetration-testing framework, and tried to sign in to more than 2,250 tenants. In some cases the attackers reached privileged cloud access in under three hours and added credentials and role changes that persist after the app itself is fixed. ConnectWise says existing archives stayed encrypted and isolated and began restoring the service in phases from 21 Oct, but third-party status trackers still showed a major outage on 25 Oct. Restoration does not remove access already established inside a tenant.

Keep ConnectWise integrations disabled until ConnectWise confirms restoration is safe, and do not delete the enterprise applications as a first step.

Supply chain

  • LiteLLM 1.107.0

    A poisoned release went out on PyPI and the official Docker images on 21 Oct. The PyPI wheels were live for under two hours and the Docker tags stayed pointed at the bad image for a few hours more. The release pipeline was altered using stolen GitHub credentials from three developer accounts. It ran a credential stealer at every Python startup, even if LiteLLM was never imported, and installed a loader that fetches and runs code from attacker infrastructure every hour. Anyone who installed it should treat every secret on that host as exposed; the clean version is 1.106.2.

  • GhostAction, GitHub Actions (peak 8 to 9 Oct)

    The credential-theft campaign first seen in September 2025 returned at far larger scale. GitGuardian and The Hacker News report about 1,900 compromised GitHub accounts used to push malicious workflows, disguised under names like security-audit.yml, into more than 30,000 repositories, with a peak on 8 and 9 Oct that reached repositories of about 3,000 users and organizations and attempted to pull 3,174 secrets: CI/CD secrets, cloud keys, and AI provider API keys. No GitHub Actions vulnerability was involved; the attackers used stolen developer credentials. Socket's count of affected maintainer accounts is lower, above 500 since 7 Oct, so the account figure depends on the measurement.

  • npm

    Eight malicious packages in a long-running data-theft campaign reached about 40,000 downloads.

  • AI coding agents

    More than 13,000 sensitive screenshots taken during agent-driven development workflows were found committed to public GitHub repositories.

  • JAMIS Prime (hosted ERP)

    Hosted JAMIS Prime environments used by government contractors have been disrupted for about a week, with access returning unevenly since late October. A post from the accounting firm Corporate Results, Inc. says reports and community updates tie the outage to a security compromise of the environment, and that customer instances are being rebuilt on new AWS infrastructure instead of cleaned in place. Some tenants have basic logins back but report intermittent performance, delayed database imports, and broken integrations and reports. No JAMIS statement was found in the sources reviewed, so the cause, scope, and number of customers affected are unconfirmed. For contractors the open questions are DCAA timekeeping and billing records kept by hand during the outage, whether the rebuilt environment keeps the FedRAMP Moderate equivalency the post says JAMIS Prime holds, and whether CUI held in an instance triggered 72-hour DFARS 252.204-7012 reporting to DC3.

Law enforcement and research

  • KillSec takedown

    On 30 Sep, in an operation called KillSwitch led by Hamburg police with Europol and Eurojust, authorities seized the ransomware group's leak site and five core servers holding at least 110 TB of stolen data. Three people were provisionally arrested; a 16-year-old is named as the suspected main operator, and Puerto Rico has requested extradition of a man arrested in the UK. The group is linked to about 1,000 suspected attacks. Police announced it on 1 Oct.

  • Pwn2Own Ireland

    98 zero-days and $1.262M paid out. The Galaxy S26 was compromised seven times and the Pixel 10 three times. Nobody registered to attack the iPhone 17.

  • Virtualine seizure, 27 Oct

    The FBI Washington Field Office seized virtualine.net, a Russian-speaking bulletproof hosting provider, in an action called Operation Omegaline with Germany's Polizei Hessen, the Dutch Politie Midden-Nederland, and the UK National Crime Agency, plus private partners. The Justice Department says its customers included ransomware groups, an infostealer operator, and a drug marketplace, and that it kept a child sexual abuse forum online despite police warnings. TRM Labs says it received more illicit cryptocurrency in 2026 than any other bulletproof host it tracks. Only the domain is confirmed seized; the reporting does not say whether servers were taken offline or customers moved.

What to do this week

  1. Patch PHP everywhere and hunt for web shells, new binaries in /tmp, and shell-spawning PHP processes on anything internet-facing since 17 Oct; the federal KEV deadline was 29 Oct.
  2. Replace any certificate chaining to eMudhra, including under the G1 RSA roots that Chrome has not yet acted on.
  3. Patch Ivanti, Cisco SD-WAN, FortiMail, NetScaler, VeloCloud, BeyondTrust, and PAN-OS, then check those devices for signs of prior compromise. Patching does not remove an attacker who is already in.
  4. Confirm GlobalProtect portals and gateways are on a build that fixes CVE-2026-0257 and review VPN logins since May for sessions that skipped MFA.
  5. Apply October Patch Tuesday, starting with the exploited Windows Shell Mark of the Web bypass (CVE-2026-96951).
  6. Audit third-party app identities in Microsoft 365 (backup, MSP, and RMM tools), rotate their secrets, and review role and credential changes since 13 Oct even if the vendor says its service is restored.
  7. Review GitHub Actions workflows added or changed since 7 Oct in every repository you own, look for unfamiliar files such as security-audit.yml, and rotate CI/CD, cloud, and AI provider secrets exposed to workflows.
  8. Check Python environments for LiteLLM 1.107.0, move to 1.106.2, remove any cook.pth, cook.py, or sitecustomize.py left in site-packages, and rotate secrets on any host that installed it.
  9. Replace long-lived admin tokens and plaintext environment variables at hosting providers with short-lived, scoped credentials.
  10. If you run hosted JAMIS Prime, document when the system went down and how manual timecards were collected, signed, and approved, ask JAMIS in writing whether the rebuilt environment keeps your FedRAMP equivalency and security boundary, and decide whether DFARS 252.204-7012 reporting applies to CUI held in the instance.
